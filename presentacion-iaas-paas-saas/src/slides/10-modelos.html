La analogía central

La nube es como buscar dónde vivir

Cuatro formas de repartir el trabajo entre tú y quien te da el servicio.

On-premises1

Construir tu casa

Tú te encargas de: terreno, obra, luz, agua, muebles, limpieza y reparaciones.

Ellos se encargan de: nada.

Control total, pero todo el trabajo y todo el gasto son tuyos.

IaaS2

Rentar un departamento vacío

Ellos se encargan de: el edificio, la estructura, la luz y el agua.

Tú te encargas de: muebles, decoración, limpieza y tus cosas.

Te dan el espacio; tú lo equipas a tu gusto.

PaaS3

Rentar un departamento amueblado

Ellos se encargan de: el edificio, los muebles y la cocina equipada.

Tú te encargas de: traer tus cosas y vivir.

Llegas con tu maleta y listo.

SaaS4

Hospedarte en un hotel

Ellos se encargan de: todo, hasta tender la cama.

Tú te encargas de: solo usar la habitación.

Llegas, usas y te vas.

IaaS · Infrastructure as a Service

Te rentan las computadoras; tú instalas todo lo demás

Qué te dan

máquinas virtuales, discos y redes, listos en minutos.

Qué haces tú

eliges e instalas el sistema operativo, lo actualizas, instalas tus programas y cuidas tus datos.

Para quién

administradores de sistemas, equipos de infraestructura (DevOps) y cualquiera que necesite control total.

Ejemplos
Amazon EC2Azure Virtual MachinesGoogle Compute Engine

Cosas técnicas

Una máquina virtual (VM) es una computadora simulada por software dentro de una computadora física real. Un solo servidor físico puede alojar muchas VM de clientes distintos, aisladas entre sí.

Resalta que en IaaS el sistema operativo es tuyo: si no instalas actualizaciones de seguridad, nadie lo hará por ti.
PaaS · Platform as a Service

Tú traes tu código; ellos lo ponen a funcionar

Qué te dan

un lugar listo para ejecutar aplicaciones: sistema operativo, entorno de ejecución, escalado, certificado HTTPS y, muchas veces, base de datos.

Qué haces tú

escribes tu aplicación y la subes (a veces basta con conectar tu repositorio de GitHub).

Para quién

desarrolladores que quieren programar, no administrar servidores.

Ejemplos
RenderHerokuGoogle App EngineAWS Elastic BeanstalkAzure App Service

Consejo

Si alguna vez publicaste una página con “conecta tu repositorio y da clic en Deploy”, ya usaste PaaS.

Si el grupo usó Render para el examen diagnóstico, menciónalo: es un ejemplo real de PaaS. Nosotros subimos el código; Render se encargó del servidor, del sistema operativo y del HTTPS.
SaaS · Software as a Service

Solo abres el navegador y lo usas

Qué te dan

una aplicación completa, lista para usarse, que se actualiza sola.

Qué haces tú

creas tu cuenta, la configuras y la usas. Nada de instalar ni de mantener.

Cómo se paga

suscripción mensual o anual, o gratis con límites (modelo freemium).

Para quién

todo el mundo: personas, escuelas y empresas.

Cuidado

Que sea fácil no significa que no tengas responsabilidades. Una contraseña débil o un enlace compartido “con cualquiera” puede exponer tus datos.

Pregunta: “¿Quién instaló una actualización de Gmail alguna vez?” Nadie: el proveedor actualiza por todos al mismo tiempo. Eso es SaaS.

Plataformas para publicar tu código sin pelearte con servidores

01

Render

Publica sitios, APIs y bases de datos conectando tu repositorio de GitHub.

02

Heroku

Uno de los pioneros del PaaS (2007). Popularizó el “sube tu código y listo”.

03

Vercel y Netlify

Especializadas en sitios y aplicaciones web modernas (React, Next.js…).

04

Google App Engine

El PaaS de Google, disponible desde 2008.

05

AWS Elastic Beanstalk

Subes tu aplicación y AWS crea y configura los servidores por ti.

06

Azure App Service

Aplicaciones web y APIs en .NET, Java, Node.js, Python o PHP, dentro de Azure.

07

Firebase y Supabase

“Backend como servicio”: base de datos, usuarios y almacenamiento listos para tu app.

Cosas técnicas

Serverless (FaaS): AWS Lambda, Azure Functions y Cloud Run functions ejecutan una sola función cuando ocurre un evento y cobran solo por el tiempo que se ejecuta. Es como un PaaS todavía más pequeño.

No hace falta memorizar la lista. La pregunta clave para reconocer un PaaS es: “¿Yo administro el servidor o solo subo mi código?”
